# Certification model

Funcprops separates a candidate, locally certified evidence and an exhaustive result. Successful replay can validate a partial cover. Always inspect the completion contract of the operation and the conclusion you intend to consume. The [result contract reference](reference/result-contracts.md) defines the fields and gives separate real, native complex, algebraic and factory-based contracts.

## Replay and trust

| Proof route | Replay does | Trusted components / limits |
| --- | --- | --- |
| Native coverage/enclosure/contour/isolation | Checks theorem premises, source binding, local witnesses and exact covers without proposing search | SymPy exact arithmetic/differentiation, outward interval primitives and implemented local lemmas |
| Finite metric and jump variation | Checks all finite values/pairs, or motion cells, signs, owned values and jump totals without the metric/partition proposer | Source-domain rules, exact symbolic limits and supported sign reasoning; other metric routes can lack standalone replay |
| Polynomial parameter geometry | Reconstructs degree strata and trace signatures, checks exact sign-prefix coverage and specialization premises | Exact rational algebra and supported guard-emptiness checks; unresolved regions remain explicit |
| Holomorphic recipes and gluing | Checks local identities/holomorphy, denominator witnesses, every overlap and exact rectangle coverage | Selected log charts, exact identity oracles and supported nonzero enclosures; recipes are supplied |
| Algebraic adapter | Rebuilds algebraization/enumeration and checks source/domain/principal-branch decisions and local certificates | algroots exact backend and declared equality oracles as well as SymPy |
| Factory-based certificates | Uses the declared verifier, sometimes recomputing through the same theorem factory | Not all factory-based replay is independent of proposing code |
| Backend/property consumers | Combine established conclusions under domain, branch and guard premises | An unknown premise must not become an unconditional conclusion |

`verify_certificate` and `replay_status` require registered concrete record types; an arbitrary object with a method named verify is not trusted. Altering theorem-relevant data must cause rejection. Diagnostic text and mathematically irrelevant metadata need not be proof premises. Unsupported evidence is not a proof that the proposition is false. `replay_status` distinguishes support, acceptance, scope and completion.

Inspect `proof_api_manifest()` for the scoped inventory. The [testing matrix](reference/testing-matrix.md) records executable obligations and remaining evidence gaps; inventory presence alone is not test coverage.

## Failure boundaries

Unresolved branch charts, source definition, parameter guards, boundary nonvanishing, exact coverage, root orders or tails prevent the corresponding completion claim. A budget stops proof search; it does not establish exclusion. Numerical approximations may propose boxes but cannot upgrade them to proofs. The package supplies internal mathematical certification, not an external formal verification of SymPy, interval arithmetic or every local theorem implementation.

See [domains and branches](guides/domains-and-branches.md), [budget behavior](guides/budgets-and-resume.md), and [the replay tutorial](tutorials/replay.md).

Worker transport preserves held source operations and exact polynomial coefficient domains. It does not upgrade a search result or change its requested domain. The [proof field reference](reference/helper-contracts.md) distinguishes stored data, derived completion and replay modes.
